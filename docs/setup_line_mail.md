# 問い合わせ一次受けの設定手順（LINE・メール）

ツナグモの「問い合わせの24時間一次受け」を使うための設定手順。野村さん自身のテスト用にも、
顧客への案内にもそのまま使える。所要時間は LINE 10分・メール 5分ほど。

設定はすべて、ツナグモにログイン →**「設定・利用状況」**の画面で行う。

---

## 0. 先に済ませること（1分）

「設定・利用状況」→「問い合わせの一次受け」で、次の2つを入れて「保存する」。

| 項目 | 内容 |
|---|---|
| 通知先メールアドレス | AIが答えられない問い合わせ・緊急の連絡をお知らせする宛先 |
| 緊急連絡先の電話番号 | 火災・ガス・水漏れ等の自動返信に載せる番号（24時間つながる番号） |

**通知先が未設定だと、緊急の問い合わせが届いても誰にも通知されない。** 画面に赤字の警告が出ていないか確認する。

---

## 1. LINE の設定

### 1-1. LINE 側でチャネルを作る

1. https://developers.line.biz/console/ にLINEアカウントでログイン
2. 「新規プロバイダー作成」→ 名前は会社名でよい（顧客には表示されない）
3. そのプロバイダーで「新規チャネル作成」→ **Messaging API** を選ぶ
4. チャネル名（**顧客に表示される**ので会社名・店舗名が無難）、説明、業種、メールアドレスを入力して作成

### 1-2. 2つの値をツナグモに登録する

| 値 | LINE側の場所 |
|---|---|
| チャネルシークレット | 「チャネル基本設定」タブの下の方 |
| チャネルアクセストークン（長期） | 「Messaging API設定」タブの一番下 →「発行」 |

ツナグモの「設定・利用状況」→「LINE公式アカウントとの連携」に貼って、**「LINE連携を登録する」**。
登録すると、同じ欄に **Webhook URL**（`https://app.tunagumo.com/webhooks/line/…`）が表示される。

### 1-3. LINE 側に Webhook を設定する

1. 「Messaging API設定」タブの **Webhook URL** に、1-2で表示されたURLを貼る
2. **「Webhookの利用」をオンにする**
3. 「検証」ボタンを押す →「成功」と出ればつながっている

### 1-4. LINE の自動応答をオフにする（忘れやすい）

「応答メッセージ」の「編集」→ LINE公式アカウントマネージャーが開く。

- 応答モード: **Bot**
- 応答メッセージ: **オフ**
- Webhook: **オン**
- あいさつメッセージ: どちらでもよい

**これをやらないと、LINEの定型文（「メッセージありがとうございます」）が代わりに返ってしまう。**

### 1-5. テスト

友だち追加（QRコードは「Messaging API設定」タブ）して、順に送る。

| 送る内容 | 期待する動き |
|---|---|
| 営業時間は何時ですか | 登録済みの公開資料の範囲で回答、または「担当者から折り返します」 |
| 更新料はいくらですか | 「担当者から折り返します」＋通知メール（金額は必ず人が答える） |
| 部屋でガスの臭いがします | 安全案内がすぐ返る＋**【緊急】**の通知メール |

そのあとツナグモの「問い合わせ」画面を開き、届いているか・画面から返信できるかを確認する。

## 2. メールの設定

### 2-1. メールサーバーの情報を用意する

**Gmail / Google Workspace の場合**

1. Googleアカウントで **2段階認証**を有効にする（https://myaccount.google.com/security）
2. https://myaccount.google.com/apppasswords で**アプリパスワード**を発行（表示される16桁を控える）
3. Gmailの設定 → 「メール転送とPOP/IMAP」→ **IMAPを有効にする**

| 項目 | 値 |
|---|---|
| 受信サーバー(IMAP) | imap.gmail.com |
| 送信サーバー(SMTP) | smtp.gmail.com |
| ポート | 465(SSL/TLS) |
| ユーザー名 | Gmailアドレス |
| パスワード | 発行したアプリパスワード（通常のログインパスワードではない） |

**その他（Xserver・さくら・お名前.com等）**
契約先の管理画面に記載のIMAP/SMTPサーバー名を使う。受信は993、送信は465（または587）。

### 2-2. ツナグモに登録する

「設定・利用状況」→「メールの即レス」に入力し、**「接続を確認して保存する」**。
保存時に実際にサーバーへ接続するので、間違っていればその場でエラーが出る。

### 2-3. テスト

別のアドレス（携帯など）から、登録したアドレス宛に送る。

| 送る内容 | 期待する動き |
|---|---|
| 営業時間を教えてください | 2分以内に自動返信（末尾に「自動応答です」と明記される） |
| キッチンで水漏れしています | 安全案内の自動返信＋**【緊急】**の通知メール |

確認すること:

- 送ったメールが**未読のまま**残っている（既読にしない仕様）
- ツナグモの「問い合わせ」画面に記録されている

---

## 3. 覚えておく仕様

- **連携した時点より前に届いていたメールには返信しない**（過去分への一斉返信を防ぐため）。テストは連携後に送ったメールで行う。
- メールマガジン・システム通知・自動返信・エラー通知には返信しない。
- 同じ相手への自動返信は24時間で3回まで（自動返信同士のループ防止）。
- ポータルサイト（SUUMO等）からの反響メールには自動返信しないが、本文から連絡先を読み取って「問い合わせ」に記録し、担当者に通知する。
- 会話の履歴は24時間、担当者へ回した問い合わせは対応済みから30日（未対応でも最長90日）で自動削除される。

---

## 4. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| LINEで返事が来ない | 「Webhookの利用」がオン／応答メッセージがオフ／「検証」が成功するか |
| LINEの定型文が返ってくる | 1-4の応答メッセージがオフになっていない |
| メールの自動返信が来ない | 「設定・利用状況」のメール欄に赤字のエラーが出ていないか。連携後に送ったメールか。迷惑メールに入っていないか |
| 接続確認で失敗する | アプリパスワードを使っているか（通常のパスワードでは失敗する）。IMAPが有効か。サーバー名・ポートが契約先の案内どおりか |
| 緊急の通知メールが来ない | 「通知先メールアドレス」が設定されているか（未設定なら画面に赤字の警告が出る） |

サーバー側のログでは、Webhookの受信・署名検証・緊急判定・通知メールの送信結果まで確認できる。
解決しない場合は、画面のエラー文とあわせて開発側で確認する。
