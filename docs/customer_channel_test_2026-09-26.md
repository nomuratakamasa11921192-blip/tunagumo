# 本人限定のLINE・個人Gmailテスト

2026-09-26 Codex。ユーザーの「おすすめでやって」により、既存営業LINEを維持する本人限定ルートと専用件名メール方式を採用した。

## 実装済み・本番未反映

- メールの新規接続は件名先頭 `[TSUNAGUMO-TEST]` を既定値にする。管理者が空欄を明示したときだけ全件対象。画面には全件化の確認を表示する。
- IMAPで件名検索し、一致候補の件名ヘッダーを確認してから本文を取得。途中に文字列があるだけのメールは除外。検索エラー時は全件取得に切り替えない。受信処理側でも記録・AI・通知・返信の前に条件を再確認する。
- 接続先・件名条件・有効化状態を変更すると受信位置を初期化し、次回確認時点以前のメールへの返信を避ける。既存アカウントはmigration 0026で空文字を付与し、従来動作を維持する。
- LINE Workerは既存署名検証を通した後、設定した本人userId・1対1トーク・テキスト・先頭 `[TSUNAGUMO-TEST]` の全条件一致だけをSaaSへ転送。テスト印を除去し、抽出した1イベントをチャネルシークレットで再署名する。他の同梱イベントは転送しない。通常相談は既存営業処理を継続する。
- 本人テストの転送失敗は営業回答へフォールバックしない。テストルートの設定未入力時は従来動作のまま。二重回答防止は既存SaaSのwebhookEventId記録を使う。

## 実接続の前提と手順

現時点で実送受信は未実施。個人メール本文の閲覧、メール送信、LINEの実送信、Webhook URL変更は行っていない。
今回のAGENTS.mdは `/opt/tsunagumo` を操作禁止としているため、実装はローカルとGitまで。本番反映は別途明示指示を得た段階で行う。

1. 本番反映が明示されたら、DB・現行API/schedulerイメージとソースを退避し、0026適用後にAPIとschedulerの両方を同じ版へ更新する。ENVは既存 `saas/.env` を維持する。APIだけを更新して旧schedulerでメールを有効にすると制限が効かないため、両方のコード照合が必須。
2. メール設定画面の「自動返信する件名の先頭」が表示され、`[TSUNAGUMO-TEST]` と確認してから設定する。受信 `imap.gmail.com:993`、送信 `smtp.gmail.com:465`、ユーザー名は本人指定Gmail。Googleアプリパスワードは本人が発行して画面に直接入力。チャットやGitへは貼らない。本人のGoogle認証が必要で、既存Gmailコネクターの認証を流用しない。
3. メールの最初の確認完了後、別の本人管理の送信元から専用件名の架空問い合わせを送る。同一アドレスから自分宛てのメールは既存ループ防止で対象外。送信元も本人の管理下であることを確認してから送信する。通常件名の私用メールが記録・返信されないことを確認する。
4. 本人のLINE userIdをLINE Developers画面などの本人情報で確定する。表示名や友だち一覧から推測しない。ユーザーIDを第三者宛てに設定しない。
5. 対象会社のSaaSに既存のLINEチャネル認証情報を安全な経路で登録する。外部出力・チャット・Gitには保存しない。SaaSのテナントIDと本人userIdをWorkerの `SAAS_TEST_TENANT_ID` / `SAAS_TEST_LINE_USER_ID` として設定する。既存secretを保持してWorkerを反映し、Webhook URLは既存営業Workerのまま維持する。
6. 本人が公式LINEの1対1トークへ `[TSUNAGUMO-TEST] 内見について教えてください` などを送る。通常問い合わせ、引継ぎ対象、架空の緊急問い合わせをそれぞれ確認する。他人の会話では試験しない。
7. 試験終了後はLINEの試験用2設定を外し、個人メールの自動返信を無効化するか連携解除する。業務用への切替は [アカウント移行メモ](personal_to_business_accounts_2026-09-26.md) に従う。
