# 自動投稿（X・Instagram・YouTube・LINE）2026-09-21、Claude

## 方針

**投稿時にAIを動かさない。** Codex も Claude Code も使わない。順番待ちのファイルを
1件取り出して送るだけなので、AIの利用上限・障害・課金に左右されない。

**置くだけで投稿される。** `sales/queue/<チャネル>/` にファイルを置けば、あとは
定期実行が送る。投稿済みは `sales/posted/<チャネル>/` へ移るので二重投稿しない。

## 承認しないと投稿されない

置いただけでは世に出ない。**目で見て承認したものだけ**が投稿される。

```
sales/drafts/<チャネル>/   … 下書き。ここに置いても投稿されない
    ↓ python scripts/review_posts.py で1件ずつ確認して承認
sales/queue/<チャネル>/    … 投稿待ち。定期実行が1件ずつ送る
    ↓ 投稿されると自動で移動
sales/posted/<チャネル>/   … 投稿済み
```

承認するとファイル先頭に `approved: <日時>` が書き込まれる。`auto_post.py` は
**この印が無いものを投稿しない**ので、うっかり下書きを投稿待ちへ置いても送られない。

`review_posts.py` は各件の内容・文字数・チャネルごとの注意（LINEは取り消せない等）を
表示してから聞く。入力を受け取れない環境では、承認せずに中断する。

## Notionで承認する（推奨）

スマホからでも承認できる。`sales/drafts/` を使わず、Notion上で完結する。

```
Notion 『状態』= 下書き    … 何も起きない
          ↓ 「承認済」にする
Notion 『状態』= 承認済    … notion_sync.py が毎時、投稿待ちへ取り込む
          ↓ 取り込むと自動で
Notion 『状態』= 投稿待ち  … auto_post.py が投稿する
          ↓ 投稿に成功すると自動で
Notion 『状態』= 投稿済
```

対象データベースは 『ツナグモ Instagram投稿予定』（`83b85a552c124499b1e9ba5bd19f7acd`）。
`チャネル` 列（x / instagram / youtube / line）を追加すれば、Instagram以外にも配れる。
列が無ければ instagram として扱う。

取り込みに失敗した行は投稿待ちへ入らず、理由がログに残る（キャプションが空、
Instagram/YouTubeで画像URLが無い、未対応のチャネル名、など）。

### ローカルの下書きもNotionで見る

`sales/drafts/` に置いた下書きは、そのままではNotionに出ない。次で送れる。

    python scripts/notion_sync.py --push            … Notionへ下書きとして作る
    python scripts/notion_sync.py --push --dry-run  … 送らず対象だけ表示

送った下書きは `sales/drafts/_sent/` へ移り、同じものが二度作られない。
これで承認する場所をNotionへ一本化できる。

列構成はDBから読み取り、**存在する列にだけ書き込む**。列名を変えても落ちない。

### 必要な設定（.env）

Notionでインテグレーションを作り、**対象データベースをそのインテグレーションへ共有**したうえで:

```
NOTION_TOKEN=ntn_...
NOTION_DATABASE_ID=83b85a552c124499b1e9ba5bd19f7acd
```

## ファイルの書き方

本文だけならそのまま書く。画像・動画を付けるときは先頭に `media:` を書き、`---` で区切る。

```
media: https://tsunagumo.pages.dev/assets/instagram/post1.png
---
本文をここに書く。
```

Xでスレッドにする場合は、本文中に `---` だけの行を入れる。

送信せず確認: `python scripts/auto_post.py --channel x --dry-run`

## チャネルごとの状態

| チャネル | 経路 | 状態 |
|---|---|---|
| LINE | Messaging API の broadcast | **すぐ使える** |
| Instagram | Buffer経由 | **すぐ使える**（認証の不具合を修正済み） |
| X | X API v2 / OAuth 1.0a | **キー4つの登録待ち** |
| YouTube | Data API | **要・再認証**（保存済みトークンがアップロード権限を持たず403） |

### Xに必要な設定

開発者ポータルでアプリを作り、権限を **Read and Write** にして4つを `.env` へ。

```
X_API_KEY=...
X_API_SECRET=...
X_ACCESS_TOKEN=...
X_ACCESS_TOKEN_SECRET=...
```

### YouTubeの再認証

`private/youtube_token.json` のスコープが足りない。`scripts/publish_youtube_short.py`
を一度手で実行し、ブラウザで動画アップロード権限を承認し直す。

### YouTubeの書き方

本文の**1行目がタイトル**、残りが概要欄になる。`media:` は動画ファイルのパス
（リポジトリからの相対パスでよい）。

公開設定は既定で **unlisted（リンクを知っている人のみ）**。自動投稿で意図せず
全世界に公開されると取り返しがつかないため、公開したいときだけ本文の先頭に
`privacy: public` と書いて明示する。

```
media: website/assets/instagram/reel1_intro.mp4
---
privacy: public
動画のタイトル
概要欄の本文。
```

## 注意

**LINEの配信は取り消せない。** 友だち全員へ一斉に届く。さらに無料プランは
**月200通まで**で、配信1回が「友だちの人数分」として数えられる。友だちが50人いれば
1回の配信で50通。毎日配信すると月1,500通となり無料枠を超えるため、
`sales/queue/line/` に置く頻度で調整すること（現在は1日1回の設定）。
