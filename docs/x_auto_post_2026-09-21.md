# X自動投稿の仕組み（2026-09-21、Claude）

## 方針

**AIを介さない。** Codex も Claude Code も動かない。順番待ちのテキストを1件取り出して
X へ送るだけなので、AIの利用上限・障害・課金に左右されない。

**Bufferを介さない。** X API へ直接送る。外部サービスの接続切れで止まらない。

公式SDKも使わず、OAuth 1.0a の署名まで標準ライブラリだけで実装した
（`saas/src/core/stripe_client.py` と同じ、依存を増やさない方針）。

## 使い方

1. 投稿したい文章を `sales/x_queue/` に `.txt` で置く（ファイル名順に投稿される）
2. あとは待つだけ。7:30 / 12:30 / 20:00 に1件ずつ投稿される
3. 投稿済みは `sales/x_posted/` へ移る（二重投稿を防ぐため）

スレッドにしたい場合は、本文に `---` だけの行を入れて区切る。

送信せず内容だけ確認する場合は `python scripts/publish_x.py --dry-run`。

## 仕様

- **文字数**: Xの数え方に合わせ、半角1・全角2で計算（全角のみなら140字）。
  超えていれば**投稿せずに停止**する。切り詰めない。
- **順番待ちが空**: 正常終了する。投稿が無い日を失敗扱いにしない。
- **認証失敗**: 401/403 のときは、アプリ権限が Read and Write か確認するよう促す。

## 必要な設定（未完了）

X の開発者ポータルでアプリを作り、**Read and Write** 権限で発行した4つを `.env` に置く。

```
X_API_KEY=...
X_API_SECRET=...
X_ACCESS_TOKEN=...
X_ACCESS_TOKEN_SECRET=...
```

これが入るまで投稿は実行されない（設定不足として停止し、何も送らない）。

## 同時に直したバグ

`scripts/publish_*.py` の `load_env` が引用符を外しておらず、`KEY="値"` と書かれた
設定を引用符ごとAPIへ送っていた。Buffer API が 401 になり、**Instagram投稿は
実際には失敗していた**。3ファイルとも修正し、Buffer認証が通ることを確認した。
