# 定期実行のPC移管（2026-09-21、Claude）

VPSでCodexを使うのをやめる方針に伴い、Codexを呼び出す2つの定期実行をVPSのcronから
このPCのタスクスケジューラへ移した。

## 移したもの

| 処理 | 時刻(JST) | タスク名 |
|---|---|---|
| 日次QA | 毎日 4:00 | `tsunagumo-daily-qa` |
| Instagram承認チェック | 8:00 / 12:00 / 18:00 | `tsunagumo-instagram-check` |

## VPSに残したもの（Codex不要のため）

| 処理 | 時刻 |
|---|---|
| DBバックアップ `backup_db.sh` | 毎日 3:00 |
| ディスク使用量チェック | 毎日 8:00 |

VPSのcronは該当2行をコメントアウトして停止した。元の内容は `/home/ubuntu/crontab.bak-<日時>`
にある。戻す場合はそのファイルから復元する。

## PC側の構成

- **日次QA専用のクローン**を作成: `C:\Users\user\事業①\tunagumo-qa`（`main` 固定）。
  `daily_qa.sh` は「main以外のブランチでは実行しない」設計のため、手動作業用の
  リポジトリとは分ける必要がある（VPSの `~/dev/tunagumo` と同じ役割）。
- Git管理外の `.env` と `saas/.env.test` はこのクローンへコピー済み。
  `BUFFER_API_KEY` はPCの `.env` に無かったためVPSから移した。
- タスクはGit Bashを直接呼ぶ。作業ディレクトリをクローンに指定することで、
  引数に日本語パスを含めずに済ませている。

## つまずいた点

`.cmd` のラッパーを経由させると動かない。cmd.exeはUTF-8で書かれた日本語パスを
正しく読めず、スクリプトに到達する前に失敗し、**ログすら残らない**。
Git Bashを直接呼ぶ形にすれば解決する。

## 注意

- **PCの電源が入っていないと実行されない。** 電源が落ちていた場合は、次に起動した
  ときにまとめて実行される設定（開始時刻を過ぎたタスクを実行する）にしてある。
- 2026-09-23までCodexの利用上限に当たっているため、それまでは両方とも失敗する。
  失敗は失敗として記録されるので、成功と取り違えることはない。
