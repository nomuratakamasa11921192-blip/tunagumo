# 業種別プロンプト集（SaaSの業種configの中身）

**使い方：** この雛形をYAMLに変換して、SaaSの業種設定ファイルにする。

```
prompt_library_by_industry.md（この文書）
　　↓ YAMLに変換
config/real_estate.yaml
config/recruiting.yaml
config/legal.yaml
config/web_agency.yaml
　　↓
顧客が「業種を選ぶ」と、対応するconfigが読み込まれる
```

**業種を増やすときも、このファイルに1業種分を追記してYAML化するだけ。**
**システム本体の開発は不要。**

## 【重要】制約部分は顧客に触らせない

各プロンプトの「制約」（法令チェック）は、**SaaSの管理者画面からのみ編集可能**にする。
顧客が消せる状態にすると、公正競争規約違反の広告が世に出る。

これが差別化の中核（→ 事業設計書「触らせない設計」）。

**共通の注意：**
- **トライアルの初期設定（30分）で、顧客の実際の成果物を見せてもらう**
- それに合わせて `company.context` を調整する
- 顧客の文体（です・ます／だ・である、絵文字の可否）に合わせる
- 各プロンプトの「制約」は業界の法令に直結するので、削らない

# 1. 不動産（賃貸仲介・売買）

**削減見込み：月20〜40時間**

## 1-1. 物件紹介文

```
以下の物件情報から、ポータルサイト掲載用の紹介文を作成してください。

【物件情報】
・物件名：
・所在地：
・最寄駅と徒歩分数：
・間取り／専有面積：
・築年数：
・賃料／管理費：
・設備：

【出力形式】
■ キャッチコピー（30字以内）
■ 本文（300〜400字）
■ おすすめポイント（3つ、各40字以内）

【制約】
・「完全」「万全」「絶対」「日本一」「最高」を使わない
  （不動産の表示に関する公正競争規約で禁止されている表現）
・駅徒歩は80m=1分で計算。実測値がなければ【要確認：徒歩分数】と書く
・提供されていない情報（管理体制、周辺施設の詳細など）を創作しない
  不明な項目は【要確認：〇〇】と明記する
・「〇〇circle分」など曖昧な距離表現を使わない
```

## 1-2. 反響対応メール

```
問い合わせ内容に対する返信文を作成してください。

【問い合わせ内容】
（メール本文をそのまま貼り付け）

【物件情報】
（該当物件の情報を貼り付け）

【出力形式】
■ 件名（30字以内）
■ 本文（300〜400字、です・ます調）
■ 社内向け補足（この返信で伝えていない事項、注意点）

【制約】
・確定していない条件（入居可能日、初期費用の総額）を断定しない
・内見の日程は候補を2〜3提示する形にする
・「必ず」「絶対に」という表現を使わない
```

## 1-3. チラシ・広告のキャッチコピー

```
以下の物件で、ポスティング用チラシのキャッチコピーを3案作成してください。

【物件情報】
（貼り付け）

【想定読者】
（例：30代ファミリー／単身の社会人／シニア夫婦）

【出力形式】
各案について：
■ メインコピー（20字以内）
■ サブコピー（40字以内）
■ この案の狙い（1文）

【制約】
・3案は訴求の軸を変える（言い回しだけ変えたものは不可）
・公正競争規約の禁止表現を使わない
・「駅近」「格安」など根拠のない優位性を示す表現を避ける
```

## 1-4. 内見後のフォローメール

```
内見いただいたお客様へのフォローメールを作成してください。

【内見時の状況】
・物件名：
・お客様の反応（気に入った点／気になった点）：
・検討状況：

【出力形式】
■ 件名
■ 本文（250〜350字）

【制約】
・急かす表現（「本日中に」「他の方も検討中です」）を使わない
・お客様が気にされていた点への回答を必ず含める
・不明な点は「確認してご連絡します」と書く
```

## 1-5. オーナーへの募集状況報告

```
物件オーナー様への月次報告文を作成してください。

【今月の状況】
・問い合わせ件数：
・内見件数：
・申込：
・実施した施策：

【出力形式】
■ 件名
■ 本文（400〜500字）
■ 来月の方針（3点以内）

【制約】
・成果が出ていない場合も事実を書く。取り繕わない
・「必ず決まります」のような保証をしない
```

## 1-6. 定期タスク（`/schedule` 設定例）

```
毎週月曜9時：
「今週の新着物件リスト（スプレッドシート）から、
 各物件の紹介文を作成して、まとめて出力してください」
```

# 2. 人材紹介・派遣

**削減見込み：月20〜35時間**

## 2-1. 求人票の作成

```
以下の条件で求人票を作成してください。

【募集条件】
・職種：
・雇用形態：
・勤務地：
・勤務時間：
・給与：
・休日：
・応募資格：
・仕事内容の概要：

【出力形式】
■ 職種名（求職者が検索する言葉で）
■ 仕事内容（箇条書き5点以内）
■ 応募資格（必須／歓迎に分ける）
■ 待遇・福利厚生
■ 選考の流れ

【制約】
・性別、年齢による限定表現を使わない（職業安定法）
  例：「〇〇歳まで」「女性歓迎」は不可
  例外的に年齢制限が認められる場合は、その理由を明記する
・「アットホームな職場」など実態が伝わらない表現を避ける
・提供されていない情報（残業時間、離職率など）を創作しない
  不明な項目は【要確認：〇〇】と明記する
・実際の労働条件と異なる記載は絶対にしない
```

## 2-2. スカウト文

```
以下の候補者に送るスカウト文を作成してください。

【候補者の経歴】
（職務経歴の要約を貼り付け）

【紹介したい求人】
（求人情報を貼り付け）

【出力形式】
■ 件名（25字以内）
■ 本文（400〜500字）

【構成】
1. なぜこの方に声をかけたのか（経歴の具体的な部分に触れる）
2. 求人の概要と、その方の経歴とどう合うか
3. 次のアクション（カジュアル面談の提案など）

【制約】
・経歴の「どこを見たか」を具体的に書く（テンプレ感を消す最重要ポイント）
・提供されていない情報（企業の内部事情、他の候補者の状況）を書かない
・「必ず内定が出ます」のような保証をしない
・年収などの条件は、求人情報にある範囲でのみ記載する
```

## 2-3. 候補者への日程調整メール

```
面接日程の調整メールを作成してください。

【状況】
・候補者名：
・企業名：
・提示できる日程：
・面接形式（対面／オンライン）：

【出力形式】
■ 件名
■ 本文（250〜300字）

【制約】
・日程は3候補以上を提示する
・所要時間、持ち物、服装を明記する
・オンラインの場合、URLの送付タイミングを伝える
```

## 2-4. 企業への推薦文

```
候補者を企業に推薦する文章を作成してください。

【候補者情報】
（経歴を貼り付け）

【企業の求める人物像】
（求人情報を貼り付け）

【出力形式】
■ 推薦理由（3点、各80字以内）
■ 懸念点と、それに対する補足（正直に書く）
■ 面接で確認いただきたい点（2〜3点）

【制約】
・懸念点を隠さない。隠すと後でミスマッチになる
・経歴書にない情報（人柄の推測など）は、面談で得た事実に限る
・提供されていない情報を創作しない
```

## 2-5. 定期タスク（`/schedule` 設定例）

```
毎朝8時：
「前日の応募者リスト（スプレッドシート）を確認して、
 各応募者への一次返信メールの案を作成してください」
```

# 3. Web制作・広告代理店

**削減見込み：月15〜30時間**

**※ 詳細版は `config_web_agency.yaml` にある。以下はプロンプト集として整理したもの。**

## 3-1. 提案骨子

```
以下のクライアントへの提案骨子を作成してください。

【クライアント情報】
・業種：
・規模：
・現状の課題（ヒアリングで聞いた内容）：
・予算感：

【出力形式】
■ クライアントの状況（推定。推定であることを明記）
■ 課題仮説（3つ以内。「〜のため、〜ができていない」の形）
■ 提案の方向性（2〜3案。狙い／想定施策／想定期間）
■ 想定される懸念と回答（2つ）
■ 要確認事項

【制約】
・全体で1500字以内
・提供されていない事実（クライアントの売上、既存施策の成果、競合名）を創作しない
  不明な項目は【要確認：〇〇】と明記
・効果を数値で断定しない。試算値の場合は前提を明示する
・施策名は具体的に（「SNS活用」ではなく「LinkedInで月4本の事例投稿」）
```

## 3-2. LP見出し・広告文

```
以下の商品・サービスのLP見出しと広告文を作成してください。

【商品情報】
・商品／サービス名：
・価格帯：
・想定顧客：
・強み（事実ベースで）：

【出力形式】
■ 想定読者（誰が、どんな状況で読むか。3行以内）
■ 訴求の軸（1つだけ選び、選んだ理由を1文で）
■ 案（3パターン）
   - 見出し（30字以内）
   - サブコピー（60字以内）
   - 狙い（1文）
■ CTA案（3つ、各15字以内）

【制約】
・景品表示法に触れる表現を書かない
  - 優良誤認：根拠のない品質の優位性（「業界最高水準」「他社を圧倒」）
  - 有利誤認：根拠のない価格の有利性（「業界最安」、常時実施の「今だけ半額」）
・「No.1」「シェア1位」は調査出典が提供されている場合のみ使用可
・断定的な効果保証（「必ず」「確実に」）を使わない
・実績・数値は提供されたものだけを使う
・3案は方向性を明確に変える（言い回しだけの違いは不可）
```

## 3-3. 進捗報告メール

```
クライアントへの進捗報告メールを作成してください。

【今週の状況】
・完了したこと：
・進行中のこと：
・遅れているもの（あれば）：
・確認が必要な事項：

【出力形式】
■ 件名（30字以内）
■ 本文（300〜500字、です・ます調、絵文字なし）
■ 社内向け補足（伝えていない事項、注意点）

【制約】
・遅れがある場合、原因・対応・見込みを必ず含める
・言い訳や責任転嫁の表現を使わない
・確定していない納期・金額を書かない（【要確認】と明記）
・相手に判断を求める場合、選択肢と期限を明示する
```

## 3-4. 定期タスク（`/schedule` 設定例）

```
毎週金曜16時：
「今週の各案件の進捗（Notionのタスクデータベース）を確認して、
 クライアントごとの週次報告メールの案を作成してください」
```

# 4. 士業（社労士・行政書士）

**削減見込み：月15〜25時間**

## ⚠️ この業種で最も重要な前提

**業務独占に触れる書類作成をAIにやらせない。**

| | 判断 |
|---|---|
| 顧客への説明文、案内文 | ✅ AIで作ってよい |
| 社内メモの整理、調査のまとめ | ✅ |
| **官公署に提出する書類の作成** | ❌ **有資格者の業務** |
| **法的判断を含む助言** | ❌ |

**すべての成果物は、有資格者が最終確認する運用にする。**
この点を契約書と研修で明記する。

## 4-1. 顧客への制度変更の案内文

```
以下の制度変更について、顧問先へのご案内文を作成してください。

【制度変更の内容】
（改正内容の要点を貼り付け。※出典を必ず添付する）

【顧問先の状況】
・業種：
・従業員数：
・特に影響がある点：

【出力形式】
■ 件名
■ 本文（400〜600字）
   1. 何が変わるか（3行以内で要約）
   2. 御社への影響
   3. いつまでに何をする必要があるか
   4. 当事務所でのサポート内容

【制約】
・提供された改正内容の範囲を超えた記述をしない
・法的な判断・助言にあたる記述をしない（「〜すべきです」ではなく
  「〜という選択肢があります。詳細はご相談ください」）
・数値・期日は提供された資料の通りに記載する。記憶で書かない
・不明な点は【要確認】と明記する
・最終的に有資格者の確認が必要な旨を前提とする
```

## 4-2. 問い合わせへの一次返信

```
顧問先からの問い合わせに対する一次返信の案を作成してください。

【問い合わせ内容】
（メール本文を貼り付け）

【出力形式】
■ 件名
■ 本文（250〜350字）
■ 社内向けメモ（確認が必要な事項、有資格者に判断を仰ぐべき点）

【制約】
・断定的な法的助言をしない
・「確認のうえ改めてご連絡します」を基本形とする
・回答できる範囲（一般的な制度の説明など）に留める
・社内向けメモに「有資格者の確認が必要な箇所」を必ず列挙する
```

## 4-3. 社内資料・調査のまとめ

```
以下の資料を、社内で共有できる形に整理してください。

【元資料】
（調査した内容、条文、通達などを貼り付け）

【出力形式】
■ 要点（3〜5点）
■ 実務への影響
■ 確認が必要な事項
■ 出典（元資料のどこから引用したかを明記）

【制約】
・提供された資料にない内容を追加しない
・条文番号・日付は資料の通りに転記する。記憶で補わない
・解釈が分かれる点は「解釈が分かれる可能性がある」と明記する
```

## 4-4. 定期タスク（`/schedule` 設定例）

```
毎週月曜9時：
「先週の問い合わせ一覧（スプレッドシート）を確認して、
 頻出していた質問をまとめてください。
 FAQに追加すべき項目があれば提案してください」
```

# 5. 全業種共通：社内AI利用ルール（雛形）

**顧客名と業種を差し替えて納品する。**

```markdown
# 【会社名】 AI利用ルール

## 1. 入力してはいけない情報

以下の情報を、生成AI（ChatGPT、Claude等）に入力しないでください。

- 顧客の個人情報（氏名、住所、電話番号、メールアドレス、生年月日）
- 従業員の人事情報（評価、給与、健康状態）
- 未公開の財務情報
- 他社から受領した機密資料
- 【業種固有：不動産ならオーナーの個人情報、士業なら顧客の相談内容等】

**判断に迷う場合は入力しない。** 担当者に確認してください。

## 2. 出力の扱い

- **生成された文章は、必ず人が確認してから使用する**
- 数値・実績・日付は、必ず一次資料で裏取りする
- 法令に関わる表現は、担当者（有資格者）が確認する
- 生成物をそのまま社外に出さない

## 3. アカウント管理

- 個人アカウントを業務に使わない
- パスワードを共有しない
- 退職・異動時は速やかにアカウントを削除する

## 4. 禁止表現（業種固有）

【不動産の場合】
- 「完全」「万全」「絶対」「日本一」「最高」
- 根拠のない「駅近」「格安」

【人材の場合】
- 性別・年齢による限定表現

【広告の場合】
- 「No.1」（調査出典がある場合を除く）
- 「必ず」「確実に」

## 5. 困ったときの連絡先

ツナグモ（野村）
連絡方法：【 】
対応時間：【平日◯時〜◯時／翌営業日中に返信】
```

# 6. 納品時のチェックリスト

- [ ] プロンプト集は顧客の**実物の成果物**を見て調整したか
- [ ] 業種固有の法令制約を入れたか
- [ ] 顧客の文体（です・ます／絵文字の可否）に合わせたか
- [ ] 空欄を埋めるだけで使える形になっているか
- [ ] 社内ルールに顧客名・業種固有の項目を入れたか
- [ ] Projectsに会社資料を投入したか
- [ ] 定期タスクを3〜5本設定したか
- [ ] 研修で**実際に手を動かしてもらった**か
- [ ] 連絡方法と対応時間を伝えたか
