# 事業の核とビジョン

## 核：AIを売らない。時間を売る

```
❌ 「AI導入のお手伝いをしています」
　→ 「AIね…うちには関係ないかな」で終わる

⭕ 「求人票を作るのに、毎回どれくらいお時間かかってますか？」
　→ 「2時間くらいですね」
　→ 「それ、30分にできます」
```

| 場面 | 言い方 |
|---|---|
| 名乗り | **「中小企業の事務作業を減らすお手伝いをしています」** |
| DM | 具体的な作業名と時間（「月20〜40時間」） |
| 提案 | 「AIで効率化」ではなく「求人票が2時間→30分」 |

**「AI導入支援」は社内の呼び名。顧客には使わない。**

## ビジョン：ITが苦手な人ほど、得をする

```
【従来】
ITに詳しい人 → AIを使いこなす → 成果が出る
ITが苦手な人 → 使えない → 取り残される

【ツナグモ】
ITが苦手な人 → 業種特化＋法令対応済み
　　　　　　→ 汎用AIを自力で使う人より、正確な成果が出る
```

### なぜ逆転できるのか

**ITに強い人が自力でやることを、システムが先にやっているから。**

| | ITに強い人が自力でやること | ツナグモ |
|---|---|---|
| プロンプト設計 | 試行錯誤して作る | **業種特化で完成済み** |
| **法令チェック** | **知識がないと無理** | **自動で弾く** |
| 品質チェック | 自分で読んで判断 | QAが検査 |
| 修正の反復 | 何度も指示し直す | 差し戻しで自動 |

```
ITに詳しい社員がChatGPTを使う
　→「駅から徒歩3分の完全な物件」→ 公正競争規約違反

ITが苦手な社員がツナグモを使う
　→「完全」が自動で弾かれる → 違反しない
```

**知識の差を、システムが埋める。**

### 汎用AIの最大の壁は「白紙」

```
【Cowork / ChatGPT】「何かお手伝いできることは？」← 白紙。ここで固まる
【ツナグモ】「物件紹介文を作る」ボタン → 入力欄 → 完成
```

### 「リテラシー不要」とは言わない

**必要なもの：** ブラウザを開ける／文字を入力できる／**出てきたものの良し悪しを判断できる**

**正確な言い方：「AIの知識は不要。業務の知識は必要」**

### このビジョンはデモでしか伝わらない

```
1. ChatGPTに「物件紹介文を作って」→ 規約違反の表現が出る
2. ツナグモに同じ依頼 → 規約に沿った文章が出る

「同じAIですが、業界のルールを知っているかどうかで変わります」
```

**商談では必ずこのデモをする。** 事前にスクショを用意（通信環境に左右されないため）。

| | HP制作を入口 | SaaSトライアル |
|---|---|---|
| こちらの作業 | **1件2〜4時間** | **ほぼゼロ** |

**ただしHP制作を捨てるわけではない。** スポット案件として受ける（後述）。

# SaaSの設計

## 技術構成

**`ai_org_spec_master.md`（2,768行・Phase 1〜16）がベース。**

| 使うPhase | 内容 |
|---|---|
| **Phase 1〜6** | 依頼受付 → 生成 → QA検査 → 承認 |
| **Phase 10** | **マルチテナント（テナント分離）** |
| Phase 7 | RAG（v2） |
| Phase 14 | 定期実行（v2） |
| Phase 12 | 外部トリガー（v3） |
| Phase 15/16 | チャットボット（v3） |

## 画面は2つに分ける

```
app.tsunagumo.jp    → 顧客用
admin.tsunagumo.jp  → 管理者用（IP制限 + 二要素認証）
```

**同じアプリ内で権限だけ分けるのは危険。** バグ1つで顧客に管理画面が見えてしまう。

## 業種ごとの差分は設定ファイルだけ

```
【共通部分】システム本体。1回作れば全業種で使える
【業種の違い】YAMLだけ（部署構成、プロンプト、禁止ワード）
```

```
顧客が登録 → 「業種を選んでください」→ 対応するconfigが自動で読み込まれる
```

**中身は `prompt_library_by_industry.md` に4業種分ある。** YAMLにするだけ。
**業種を増やすのは設定1本追加のみ。開発不要。**

## 【設計の肝】何を顧客に触らせるか

```
汎用ツール：全部触れる → 顧客が法令チェックを消せてしまう
ツナグモ  ：法令部分は触れない → 消せない
```

**「制限すること」が価値になる。** 汎用ツールには構造的に作れない。

| 項目 | 顧客が触る | こちらが設定 |
|---|---|---|
| **業種の選択** | ❌ | ✅ 初期設定時 |
| 会社名・サービス・価格帯 | ✅ | |
| **文体** | ✅ **選択式**（自由記述にしない） | |
| プロンプトへの**追記** | ✅ **テキスト欄1つだけ** | |
| **プロンプト本体** | ❌ | ✅ |
| **禁止ワード・法令チェック** | ❌ **絶対に触らせない** | ✅ |
| 資料のアップロード（RAG） | ✅（v2） | |

**原則：触らせるのは「足す」だけ。「変える」「消す」は触らせない。**

**理由：** 不動産で「完全」が通ってしまえば、公正競争規約違反の広告が世に出る。

|---|---|

**動画編集を入れてよい理由：** 顧客はコードに触らない。ボタンを押すだけ。
**注意：** VPSにGPUがないので遅い（1分の動画で3〜8分）。**非同期にして「完成したら通知」。**

### v3（1年以内）

| 機能 | 期間 |
|---|---|
| **HP制作（テンプレート方式）** | +2〜3ヶ月 |
| チャットボット（LINE/Web） | +2〜3週間 |
| 外部トリガー | +2〜3週間 |

**HP制作の実装：**
```
テンプレート選択 → 会社情報入力 → 写真アップ
→ 文章はSaaSが生成 → プレビュー → Cloudflare Pagesに自動デプロイ
```
**顧客はコードに触らない。** デプロイ先は顧客名義のアカウントにする。

### 【絶対に入れない】2つ

| | 理由 |
|---|---|
| **DM自動化を顧客に渡す** | **顧客のInstagramアカウントが凍結される。**賠償問題 |
| **コード実行機能** | 事故時に責任を負えない。**「触らせない設計」と矛盾する** |

**自分でやるのは自己責任。顧客に渡すのは別の話。**

## 【最重要】テナント分離

**A社のデータがB社に見えたら、事業が終わる。**

`ai_org_spec_master.md` Phase 10 が該当。

- 全テーブルに `tenant_id` ＋ **PostgreSQLのRow Level Security**
- **`SET LOCAL` をトランザクションスコープで使う**
  （コネクションプールで使い回すと、前のリクエストのtenant_idが残って漏洩する）
- **テナント分離テスト5項目**を全部グリーンにしてから公開

**ここだけは絶対に手を抜かない。**

# 営業

## 全体の流れ

```
DM → サイトを見る → トライアル申込 → 初期設定 → 2週間 → 課金
```

## トライアルの設計

### クレカ登録は「なし」にする

| | 登録あり | 登録なし |
|---|---|---|
| 申込数 | 少ない | **多い** |
| 有料転換率 | 高い（40〜60%） | 低い（5〜15%） |
| 印象 | 警戒される | **入りやすい** |

**実績ゼロの段階では「登録なし」。** まず使ってもらうことが優先。
**最初の10社は、転換率より事例を優先する。**

### 【最重要】離脱を防ぐ運用

**普通のSaaSトライアルは、7〜9割が離脱する。**

```
【失敗パターン】
無料登録 → 1回使ってみる → 忙しくて放置 → 2週間経過 → 離脱
```

**避け方＝初期設定をこちらがやる。**

```
【0日目】申込
　↓
【1〜2日目】30分のオンラインで初期設定
　・業種を選ぶ
　・会社情報を登録
　・**その場で1本、実際に作ってみせる**
　↓
【3日目】「使えてますか」と連絡
　↓
【7日目】管理画面（①）で利用状況を確認
　・使われていなければ、こちらから声をかける
　↓
【12日目】成果の確認「何時間くらい減りましたか」
　↓
【14日目】課金の案内
```

**管理画面①（横断ダッシュボード）が、離脱防止の武器になる。**
「使われていない」を検知できるのは、SaaS運営者だけの特権。

### 課金の案内の仕方

```
「2週間で〇本お作りいただきました。
 時間にすると、だいたい〇時間くらいでしょうか。

 継続される場合、ライトプラン月3万円からになります。
 今の使い方だと、スタンダード（月6万円）が合いそうです」
```

**利用実績の数字を出す。** 「どうですか」より説得力がある。

## DM文面

### 基本形（4業種共通の構造）

```
突然のご連絡失礼いたします。
〇〇様のサイトを拝見しました。〔具体的な感想を1行〕

埼玉県春日部市で、中小企業の事務作業を減らすお手伝いをしている
高校3年生の野村と申します。

〔業種〕の方から、〔具体的な作業〕に
月〇〜〇時間かかっているというお話をよく伺います。

その作業を短縮するシステムを提供していまして、
2週間無料でお試しいただけます。
初期設定は全部こちらで行いますので、
お手間は最初の30分だけです。
```

# 優位性・弱点・克服策

## 大前提：技術では勝てない

LangGraphは誰でも使える。AISAKU（月5万）、Slack AI-Skills、Relevance AI、大塚商会が既にいる。
**「唯一無二の技術がある」と言った瞬間、詳しい相手に崩される。**

## 比較対象は3種類ある

| 相手 | 性質 | 競合か |
|---|---|---|
| CrewAI / LangGraph | フレームワーク | ❌ **材料であって競合ではない** |
| Claude Code / Verdent | 開発ツール | ❌ 使う人が違う |
| **YouTubeのAI組織** | 個人の作業効率化 | △ 顧客層が違う |
| **Cowork / Relevance AI** | 汎用SaaS | ✅ 競合 |
| **AISAKU / 大塚商会** | 業種横断SaaS | ✅ **最も直接的** |

## ① 対 YouTubeのAI組織（サブエージェント版）

**構造の性能：ツナグモが上**

| | サブエージェント版 | ツナグモ |
|---|---|---|
| 並列実行 | ✅ | ✅ |
| **差し戻しループ** | ❌ | ✅ |
| **中断して数日後に再開** | **❌ セッションが終わると消える** | ✅ |
| **承認フロー** | ❌ | ✅ |
| **監査ログ** | ❌ | ✅ |

**自由度：サブエージェント版が上**（ツールを何でも追加できる）

**「自由度」と「構造の性能」は別の軸。** 混同しない。

**決定的な違い：顧客に渡せるかどうか**
```
サブエージェント版 → Claude Code＋ターミナル＋YAML編集 → 中小企業には無理
```

**営業での言い方（「高性能」と言わない）：**
```
「YouTubeの方法は、ご自身のPCで動かすものです。パソコンを閉じたら止まります。
 うちは、部長さんが3日後に承認ボタンを押しても続きから動きます。
 誰が承認したかの記録も残ります」
```

|---|---|---|---|

## 【重要】「Claude Codeでいいのでは」への回答

**この疑問は、商談でも自分の中でも必ず出る。**

```
Claude Codeを使える人 = ターミナルが使える = エンジニア
　↓
その人たちは既に使っている
　↓
そもそも顧客候補ではない
```

**春日部の不動産会社の社長は、ターミナルを開けない。**

| サービス | 「もっと自由な代替」 | 結果 |
|---|---|---|
| freee | エクセルでできる | **年商数百億** |
| Kintone | Accessでできる | **大企業が採用** |

**「もっと自由なツールがある」ことと「売れる」ことは関係がない。**
**むしろ制限があるほうが売れる。**

```
【たかまさくん視点】「文章生成だけ？ Claude Codeなら全部できるのに」
【顧客視点】「ターミナル？ 何それ」
```

**機能の少なさに不安を感じたら、ここに戻る。**

# 迷ったときの5つの確認

**新しい事業アイデアが浮かんだら、これを通す。5分で判断できる。**

1. **今の事業で、何件納品した？** → 0件なら、まだ判断材料がない
2. **その領域に予算はあるか？ 決裁は早いか？** → 社会的意義と事業性は別
3. **3つ目の変数（高校生／春日部／既存スキル）を掛けられるか？**
4. **B2CかB2Bか？** → B2Cは1万人、B2Bは10〜20社。資本がないならB2B
5. **今のSaaSで対応できないか？** → できるなら、新規開発は不要
