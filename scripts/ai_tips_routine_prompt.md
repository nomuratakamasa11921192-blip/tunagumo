# AI活用ヒント 下書き自動作成ルーティン(CronCreateで7日ごとに再設定が必要)

このファイルは、CronCreateのジョブが7日で自動的に消えた後、同じ内容で再作成するための
控え。新しい会話でも、このファイルの内容をそのままCronCreateのpromptとして渡せば
同じ自動化を再開できる。

**2026-09-01変更(重要・コンテンツ方針): 不動産特化ピボットに伴い、投稿タイプを
「不動産50% / 実績・技術30% / 横展開予告20%」の3種類でランダムに選ぶ方式に変更した。**
実績・技術タイプは野村隆真個人を前面に出し、SaaSの開発の裏側・実際の機能を紹介する
(PDFで壁打ちした「AIファウンダーとしての発信」路線を、不動産営業を主軸にしつつ一部
取り入れたもの)。横展開予告タイプは他業種への応用可能性を匂わせる(確約はしない)。
下記「ジョブ本体プロンプト」節は2026-08-30時点の内容のままなので、次回①を再設定する際は
このファイルではなく、直近のセッション会話に残っている2026-09-01の実際のCronCreate
promptを参照するか、上記の配分をこの節に手動で反映してから使うこと。

**2026-08-30変更(重要): 夜間動画生成ジョブ(③)は廃止した。** 日常のAI活用ヒント投稿は
画像のみとする方針に変更されたため。動画は「自社サービス(ツナグモ)紹介」の時だけ、
必要に応じて手動で作る特別枠に変更(自動生成はしない)。あわせて、②のNotion承認
ポーリングジョブからもYouTube投稿ステップを削除し、Instagram(Buffer)投稿のみに
簡略化した。

**このルーティンは2つの独立したcronジョブで構成される(2026-08-30〜)**:
1. 画像下書き作成ジョブ(毎日1回) — 本ファイルの「ジョブ本体プロンプト」
2. Notion承認ポーリングジョブ(30分おき、Instagram投稿のみ) — 下記「② Notion承認ポーリングジョブ」参照

~~3. 夜間動画生成ジョブ~~ 廃止(下記「③」の節は経緯の記録として残すが、再設定はしないこと)

2つともセッション専用・7日で自動消滅するので、再設定するときは両方忘れずに。

## ① 下書き作成ジョブの再設定手順(次回このファイルを見つけたら)

1. `date` コマンドで現在時刻を確認
2. 以下の「ジョブ本体プロンプト」をそのまま `CronCreate` の `prompt` に渡す
3. `cron`は毎日1回、キリのよくない分に設定する(例: "47 18 * * *" = 毎日18:47)
4. ユーザーに「7日後にまた消えるので、そのときはまた声をかけてください」と伝える

  投稿(Buffer送信)を自動実行しない。

  止める**

  受けてから(cronジョブ本体からは呼ばない。承認は必ずチャット上またはNotion上の
  人間判断を経由する)

## ジョブ本体プロンプト

あなたは「ツナグモ」のInstagram運用担当です。以下を1回分、順番に実行してください。

### 1. リサーチ
WebSearchで、今日時点の実際に存在する「AI・AIエージェントに関する時事ネタ・活用方法・裏技」を1つ探す。
新しいAIモデル/エージェント機能のリリース、実務での賢い使い方、意外と知られていないコツ、などを優先する。
中小企業の経営者(不動産・人材紹介・士業・Web制作・その他業種問わず)にとって関心を持てる内容を優先する。
架空の情報は絶対に作らない。検索で実際に確認できた内容のみ使う。

**2026-08-30追加**: 海外のバズっている動画・投稿をそのまま翻訳・模倣することはしない(著作権・
プラットフォームの重複検出の観点でリスクがある)。ただし、バズっている動画の**構成・フックの型・
尺・テンポといった「型」を参考にする**のは問題ない。中身(トピック・セリフ)は毎回WebSearchで
確認した実話・実データに基づいて自分で書くこと。

直近の投稿と重複しないよう、`sales/ai_tips_history.md` を読んで、既出のトピックを避ける
(ファイルが無ければ新規作成してよい)。

### 2. キャプション作成
以下のルールで日本語のInstagramキャプションを1本書く:
- 「絶対」「必ず」「100%」「国内完結」は使わない
- フックになる一文から始める(数字・驚き・問いかけ等)
- ヒントの中身を簡潔に説明する(3〜6文程度)
- 自然に感じられる場合のみ、ツナグモ(不動産・人材紹介・士業・Web制作向けAI SaaS)に軽く触れる
  (毎回無理に営業しなくてよい。純粋に有益な情報発信の回があってもよい)
- 関連ハッシュタグを3〜5個
- 最後に一行、`詳しくはプロフィールのリンクから` を入れる

キャプションは `sales/ai_tips_drafts/YYYY-MM-DD.txt` に保存する。

### 3. 画像生成(Higgsfield)
`generate_image` (model: nano_banana_pro, aspect_ratio: "4:5") で、今日のヒントの雰囲気に合う
写真を1枚生成する。プロンプトは以下のスタイルを踏襲する(サイトのトーンと統一するため):

```
Editorial documentary photograph, warm muted color grade in cream and soft navy tones matching
a minimalist Japanese business website. [今日のヒントに合う具体的なシーン、例: a Japanese
professional reviewing documents at a desk]. Soft natural window light, shallow depth of field,
no visible text or logos, quiet composed atmosphere, shot on medium format film, muted warm
color palette (cream, soft brown, ink navy), no harsh shadows.
```

生成した画像に、以下を合成する(1080x1350、既存の`website/assets/tips/tip_template_2.jpg`と
同じレイアウト・配色・フォント[Noto Sans JP]を踏襲):
- 上部: 生成した写真(cover、高さ760pxでmask固定クロップ)
- 下部: クリーム背景(概ね#F6F1E8)に「AI活用のヒント」の丸ピル(タン色背景・こげ茶文字) +
  今日のヒントの見出し(短く、1〜2行、ネイビー太字) + 「詳しくはキャプションをご覧ください」 +
  フッターに`tunagumo. — 不動産・人材紹介・士業・Web制作向け AI SaaS`

**実装方法(2026-08-28に実際に動作確認済み。「higgsedit」という専用ツールは存在しないので注意)**:
`mcp__higgsfield__sandbox_exec`(Higgsfieldのクラウドサンドボックス、python3+Pillow+curl+ImageMagick
が使える)を使い、1回のシェルコマンドの中で①生成した写真をcurlで取得、②Google Fontsの
`https://fonts.googleapis.com/css2?family=Noto+Sans+JP:wght@400;700&display=swap`をcurlして
CSSからNoto Sans JPのRegular/Bold ttf URLを抽出しダウンロード、③Python(PIL)で上記レイアウトを
描画、④`mcp__higgsfield__media_upload`で事前取得したpresigned URLへ`curl -X PUT`でアップロード、
という流れを1コマンドにまとめて実行する。アップロード後は`media_confirm`を呼び、
返ってきたcloudfrontの公開URLをローカルの`curl`で`sales/ai_tips_drafts/YYYY-MM-DD.jpg`に
保存する(sandboxはコマンド終了後10秒ほどで消えるため、成果物は必ずアップロードしてから
ローカルに取りに行くこと)。

### 4. 投稿はしない(下書きまでで停止)
このジョブ自体は投稿しない。画像・キャプションが `sales/ai_tips_drafts/` に揃った状態で処理を止める。
承認され次第、以下のいずれかの経路で投稿される(詳細は本ファイル冒頭「前提」参照):
- 野村さんがチャットで「OK」等と発言 → その場でClaudeが実行
- 野村さんがNotionで「状態」を「承認済」に変更 → 30分おきの②ポーリングジョブが検知して実行
どちらの経路でも、実行コマンドは共通:
```
python scripts/publish_via_buffer.py --media-url "<Higgsfieldストレージの公開URL>" --caption-file "sales/ai_tips_drafts/YYYY-MM-DD.txt" --yes
```

### 5. 履歴記録・Notion登録
`sales/ai_tips_history.md` に、日付・トピック・下書き作成できたかどうかを1行追記する
(「投稿済み」ではなく「下書き作成済み」と書くこと)。

続けて、Notionデータベース「ツナグモ Instagram投稿予定」
(data source: `collection://fcaa6685-2a01-4ca4-b48a-0958a86b80ad`)に1行追加する:
- 投稿タイトル: `YYYY-MM-DD: <今日のヒントの見出し>`
- キャプション: `sales/ai_tips_drafts/YYYY-MM-DD.txt`の内容そのまま

## 字幕焼き込みの注意点(2026-08-29判明、重要なハマりどころ)

`drawtext`フィルターで`text='...\n...'`のように**バックスラッシュn(`\n`)を直接文字列に
書いても改行として解釈されず、文字通り「n」という文字が挿入されてしまう**(実際に事故った:
「いきなり全社員でnやろうとしていません」のように"n"が混入し、かつ改行されないせいで
1行に収まらずテキストが画面の左右にはみ出して切れる不具合が発生した)。

**対策**: `text=`ではなく`textfile=`オプションを使い、実際の改行文字(`printf 'A\nB\nC' > cap.txt`
のように`printf`で作る)を含むテキストファイルを読み込ませること。日本語字幕は1行あたり
13〜15文字程度に収まるよう事前に改行位置を決めておく(縦型9:16・fontsize 54〜58程度の場合の目安)。
例:
```bash
printf 'AI導入、\nいきなり全社員で\nやろうとしていませんか?' > cap1.txt
ffmpeg -y -i scene1.mp4 -vf "drawtext=fontfile=NotoSansJP-Bold.ttf:textfile=cap1.txt:fontcolor=white:fontsize=58:box=1:boxcolor=black@0.55:boxborderw=20:x=(w-text_w)/2:y=h-480:line_spacing=16" -c:a copy scene1_sub.mp4
```
仕上がりは必ずffmpegでフレームを1枚抜き出して(`-vf "select=eq(n\,60)" -update 1 -vframes 1`)、
実際に読める字幕になっているか目視確認してから最終アップロードすること(今回もこの確認で
不具合を発見・修正できた)。
